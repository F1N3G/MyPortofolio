CulturalHub

A web platform for discovering and booking cultural events across Romania.

Laravel 12 PHP 8.3 MySQL Blade Tailwind CSS Alpine.js PHPUnit

Overview

CulturalHub lets visitors browse theatre, opera, cinema, concert and exhibition events across more than 35 Romanian venues, pick their own seats on a rendered hall map, and book online. Organizers publish and manage their own events, while administrators oversee the full catalogue through a dedicated panel.

This is the largest project I have built, and it also serves as my bachelor's thesis. It grew beyond a single application: the same domain is now covered by a native Android client and a Python recommendation engine, both consuming or extending this platform.

Features

  • Seat-selection booking — hall layout presets for small, medium and large theatres and cinemas, with instant confirmation.
  • Role-based access — Admin, Organizer and User, each with a distinct set of permissions enforced through policies.
  • Event management — full CRUD for events, venues and categories, with image upload and cleanup on delete.
  • Discovery — filtering by category, city and date across venues in Bucharest, Cluj, Timișoara, Iași and elsewhere.
  • Admin dashboard — catalogue statistics, reporting and user management.

Architecture

The seat-selection feature drives the domain model. Each venue has a hall layout; events held at that venue inherit it, and reservations store the specific seats assigned rather than just a quantity. Keeping the assignment at the data level means double-booking is prevented by the schema itself, not only by application checks.

Authorization lives in Laravel policies rather than scattered controller conditionals, so an organizer can only ever reach their own events. Event validation is isolated in a form request class, keeping controllers thin.

What I learned

Modelling seats properly turned out to be the difference between a demo and something that could actually be used. My first approach stored a booking count per event, which fell apart as soon as two people needed specific, different seats. Reworking it into explicit seat assignments made the concurrency question disappear.
