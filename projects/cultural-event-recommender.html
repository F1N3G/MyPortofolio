Cultural Event Recommender

A hybrid recommendation engine combining rule-based scoring with content-based text similarity.

Python scikit-learn pandas Streamlit matplotlib NumPy

Overview

This project extends the CulturalHub domain with a recommendation layer. Given a user's preferred category, city and budget, it ranks events by how well they match — and, when nothing matches closely enough, it falls back to popularity rather than returning an empty result.

It combines two independent approaches. The first is a weighted scoring function over structured attributes. The second treats each event's text as a document and measures similarity against a query built from the user's preferences.

Features

  • Preference scoring — weighted matching over category, city and budget, blended with a normalised popularity component.
  • Content-based matching — TF-IDF vectorisation and cosine similarity over event title, category, description and location.
  • Popularity fallback — a weighted score over rating, bookings and views, used when no personalised match is available.
  • Interactive interface — a Streamlit app with live filtering, dataset metrics and user selection from the data.

How the scoring works

Each event receives a score from weighted attribute matches plus a popularity component. Rating, bookings and views are min-max normalised so that events stay comparable regardless of their absolute values:

score = category_match × 40 + city_match × 25 + budget_match × 20 + (rating_norm × 8 + bookings_norm × 4 + views_norm × 3)

Filters are applied progressively rather than all at once. If the budget filter would leave no candidates at all, it is relaxed instead of returning nothing — a user with an unrealistic budget still gets useful suggestions.

Architecture

src/ ├── data_loader.py # CSV loading ├── preprocess.py # Cleaning, type coercion, content field ├── recommender.py # Preference-based scoring ├── text_recommender.py # TF-IDF + cosine similarity ├── statistics_recommender.py # Popularity ranking └── main.py # CLI entry point app/ └── streamlit_app.py # Interactive interface

What I learned

Normalisation mattered more than I expected. Without min-max scaling, an event with thousands of views dominated the ranking regardless of how well it actually matched the user's preferences. Scaling each signal to a common range let the weights express intent instead of accidental magnitude.
